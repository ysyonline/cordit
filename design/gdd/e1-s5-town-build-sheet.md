## 1. 施工总览

### 1.1 目标（一句话）
在 `scenes/maps/town.tscn` 里做出一张 64×48 小镇白盒图 + 远角内嵌 2 间 12×9 室内，五层结构齐备、y-sort 正确、门=简版 teleport + 相机限区，主街环线走完约 90s，NPC/调查/宝箱 19 个点位全部预留到位。

### 1.2 硬性裁决（不得违背，来源见括号）
1. 室内**不建独立场景**，内嵌同图远角（GDD §3.1 勘误声明）。
2. 草地/植被**只用 forest_tiles**，不用 town_tiles 里的草地（美术守则 §一 草地取材指定）。
3. teleport 本 Story 允许**简版**（切位置+切相机限区），正式时序 E4-S6 再做（EPIC-1 验收③）。
4. NPC **只摆位不实现交互**（E1-S6 的事）；对话 JSON 不在本 Story 范围。
5. 五层结构与门-teleport 是**降级也不可砍**的保底件（EPIC-1 收口预案）。

### 2.2 建一个共享 TileSet 资源（省时做法）
Ground/GroundDeco/WallsObjects/Above 四个 TileMapLayer **共用同一个 TileSet 资源**（一个资源可含多个图集）。层与层的区别只在于"把哪类 tile 画到哪个节点"，不在资源上区分。存为 `res://assets/tiles/town_map_tileset.tres`。

### 2.3 物理层配置（编辑器操作）
1. 场景面板选中 `Ground`（TileMapLayer）→ 检查器 → **Tile Set** 属性 → 下拉选"新建 TileSet"→ 点击进入底部 **TileSet 编辑器**。
2. TileSet 编辑器左上 **TileSet** 分区 → 确认 **Tile Size = 16×16**。
3. **图集（Atlas）** 分区 → 点 **+** → 选 `assets/tiles/town_tiles.png` → 弹窗确认切分：16×16、边距 0、间距 0 → 生成 32×32 网格。同法添加 `forest_tiles.png`（15×10）。
4. **物理层**：TileSet 分区 → **Physics Layers** → 点 **添加** → 生成"物理层 0"→ 检查器里设 **collision_layer = 1**（只勾第 1 位）、**collision_mask = 0**。这与玩家碰撞层 bit1（世界墙体）对齐，玩家即被挡。
5. **给 tile 挂碰撞**：TileSet 编辑器用**选择工具**框选一类 tile（如建筑墙面）→ 右侧 **Physics** 分区 → 选物理层 0 → 添加碰撞多边形 → 拖出覆盖整格的矩形。若 4.7 的框选批量不生效就逐格画（需挂碰撞的 tile 约 25-35 个，预算 15 分钟）。
6. **Y Sort Origin（y-sort 正确的关键）**：仍用选择工具，框选**所有将画进 WallsObjects 的 tile**（墙面/门窗/树干/井/喷泉/柜台/箱桶/招牌）→ 右侧 **渲染（Rendering）** 分区 → **Y Sort Origin = 8**（默认 0=tile 中心，+8 即贴 tile 底边）。这样"角色站墙后/树后被遮挡"才成立（架构 A6 原点规则）。Above 层 tile 不用设（z=+10 恒在最上）。
7. Ctrl+S 保存资源为 `town_map_tileset.tres`。之后在 Ground/GroundDeco/WallsObjects/Above 四个节点的 Tile Set 属性里都选它。

### 2.4 碰撞多边形建议

| 多边形 | 适用 tile | 理由 |
|---|---|---|
| **满格 16×16** | 建筑墙面、神殿墙体、井体、喷泉 4 格、边框树干、箱/桶、柜台、书架、床 | 白盒期统一满格，最不容易出穿模 |
| **半格下沿 16×8（贴 tile 底）** | 围栏、花坛、矮墙 | 允许角色"贴着"矮障碍站，视觉不死板；可选项，时间紧全用满格 |
| **无碰撞** | 门洞格（可进建筑的门）、全部草地/道路/地毯、树冠（Above 层一律不挂）、存档水晶（占位期） | 门洞靠 teleport 进出，不挡路；树冠在头顶层 |

> 注意：**门洞格不挂碰撞**（客栈门 29,17、民居A门 12,17）；锁闭建筑的门（B3/B4/B5/B7/B8/B9/B10）门格挂碰撞即可，S6 再换"调查提示锁着"。

### 3.4 主街环线（~90s 的口径与走法）

**先说口径（重要）**：任务书按"90s × 4.5 tile/s ≈ 405T 纯走"折算。但 64×48 图的街道网一越不重复地走完上限约 270T——405T 纯走必然大面积重复踩街，密度感反而造假。故本方案采用 **A 案**：

> **A 案（推荐）**：环线纯走 ≈ 272T ≈ 60s ＋ 19 个点位自然驻足（读气泡/转向，均值 1.5s ≈ 29s）≈ **89s ≈ ~90s**。EPIC 验收写的是"主街环线 ~90s 可走通"，体验时长达标即绿。
> **B 案（备用，若用户坚持 405T 连续走）**：在 A 案上加——草甸外圈绕行 +60T、广场第二圈 +16T、四栋锁门建筑门前折返 +32T ≈ 380T ≈ 84s，再放宽草甸即 ≈405T。代价：重复路段约 35%。**待用户拍板，默认按 A 案施工。**

### 3.6 远角室内 2 间（12×9 各一）

## 4. 五层结构搭建步骤（节点树逐条）

```
Map_Town (Node2D)                          # scenes/maps/town.tscn 根节点

├── Ground (TileMapLayer, z=-10)           # 草地底(forest) + 室内地板
├── GroundDeco (TileMapLayer, z=-9)        # 道路/广场砖/草甸土路 + 室内地毯

    ├── Door_Inn (Area2D)                  # (29,18) → 室内A
    ├── Door_HouseA (Area2D)               # (12,18) → 室内B

    └── HouseA_Exit (Area2D)               # (85,30)室内B → (12,19)
```

**各层铺什么（对照 A6）**：
- **Ground**：主图草地全填（forest_tiles 草地 3-4 种变体混铺防贴图感）＋室内地板。
- **GroundDeco**：3.2 全部道路/广场/土路＋室内地毯；水/花坛底饰。
- **WallsObjects**：全部建筑立面行、边框树干、草甸树、喷泉、井、招牌、柜台、家居、存档占位、宝箱 tile。**这一层的每个 tile 都要在 TileSet 里设过 Y Sort Origin=8**。
- **Above**：屋顶上沿行（每栋顶 2 行）、树冠、烟囱。不挂任何碰撞、不用 y-sort。
- **Triggers**：本 Story 4 个门 Area2D；survey/chest/savepoint/gate 的触发器 S6/E2/E4 再进本层。
- **碰撞层归属再强调**：没有独立"碰撞层"——碰撞全部在 TileSet 资源的物理层里配（2.3/2.4），玩家角色自动被挡。

**y-sort 正确的三个目检点**（铺完立即可验，F5 跑图）：
1. 玩家站客栈北侧 (29,12)：身体被屋顶/立面上部遮挡（Above 恒盖 + WallsObjects origin 贴底）。
2. 玩家站喷泉南侧 (27,29)：玩家盖住喷泉下沿（玩家脚底 y > 喷泉 tile 底 y）。
3. 玩家贴边框树北侧行走：树冠始终在头顶（Above），树干在玩家转身绕行时正确前后遮挡。

## 5. 相机限区与 teleport 简版

### 5.1 Camera2D limit 数值表（改 player.tscn 实例内的 Camera2D）

| 区域 | limit_left | limit_top | limit_right | limit_bottom | 像素范围 |
|---|---|---|---|---|---|
| 主图（默认） | 0 | 0 | 1024 | 768 | 64×48 tile |
| 室内A（客栈一楼） | **1056** | **0** | **1696** | **360** | 黑幕框=视口尺寸，相机实际静止、房间居中 |
| 室内B（民居A屋内） | **1056** | **188** | **1696** | **548** | 同上 |

> 说明：室内 limit 不是房间自身的 192×144（那是门的"像素范围"），而是**黑幕框**的 640×360——因为 limit 钳的是取景框四边，取景框本身就有 640×360 大。房间在框内居中，视觉上即"相机锁死在房间"。E4-S6 做正式时序时若想改 zoom 或做进屋淡入淡出，布局无需动。

### 5.2 门 trigger 简版行为说明（4 个 Area2D 通用）

| trigger | 位置(tile)/形状 | 触发 | 行为 |
|---|---|---|---|
| Door_Inn | (29,18) 16×16 格 | 玩家 body_entered | 玩家 position → (85,17)室内A；相机 limit 换室内A 行；`camera.reset_smoothing()` 防平滑甩镜 |
| Inn_Exit | (85,18)室内A 门垫 | body_entered | 玩家 → (29,19)；limit 换主图行；reset_smoothing |
| Door_HouseA | (12,18) | 同构 | → (85,29)室内B；limit 换室内B 行 |
| HouseA_Exit | (85,30)室内B | 同构 | → (12,19)；limit 换主图行 |

**防弹回设计**：入口落位点永远在门垫 trigger 的**上一格**（(85,17)≠(85,18)），传送落位不会压在出口 trigger 上；出口落位 (29,19) 也在门 trigger (29,18) 之外一格——进出都不会原地死循环。

**简版参考伪代码**（挂 Map_Town 根，约 40 行；正式时序 E4-S6 重做，此处仅保"可进可出"）：

```
# town_map.gd —— E1-S5 简版 teleport；TODO(E4-S6)：替换为事件时序（黑屏过渡+map_ready+自动存档）
@export var limits_main  := Rect2i(0, 0, 1024, 768)     # 四值即 limit_left/top/right/bottom
@export var limits_inn   := Rect2i(1056, 0, 1696, 360)
@export var limits_house := Rect2i(1056, 188, 1696, 548)
# 每个 Area2D body_entered → 读 trigger 元数据(target_pos, target_limits)
# → player.global_position = target_pos → 换相机四项 limit → camera.reset_smoothing()
```

**给 E4-S6 的衔接注释**（写进 town_map.gd 头部）：
1. 简版 teleport 无转场、无 `map_ready`、无自动存档——正式时序按探索 GDD §3.4：teleport 动作 → 载图/落位 → 地图广播 `map_ready` → `SaveManager.save()`（同图室内传送是否触发自动存档，E4-S6 裁决）。

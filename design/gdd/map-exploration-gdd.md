# GDD：地图探索/遇敌（设计部分，22h）

> 作者：文策渊（design-strategist）｜阶段：系统设计｜汇编：游承峰（team-lead）
> 依据：概念文档定稿 + 架构 A5/A6/A7 + phase2-3 对齐报告两裁决
> 工时口径：18h 探索 + 4h 遇敌，不放大

---

## 1. 概述与设计目标
- **定位**：承载支柱三"小而密的探索"+ 概念文档机制层"可见敌人"。对齐架构 A6 五层结构与 A5 遇敌载荷。
- **设计目标**：① 密度达标——玩家每走 30 秒有一次发现；② 可见敌人提供"绕开/迎击"的选择权；③ 进图自动存档让失败读档（战斗 GDD 3.5）免费成立。
- **不做什么**：寻路/视野锥 AI、随机暗雷、小地图、任务日志、地图间快速旅行、昼夜。

## 2. 玩家体验目标
- 方向感靠地图设计不靠 UI：道路有地标（断桥、石像），遗迹有"往深处去"的纵向暗示。
- 战斗前有选择：看得见的敌人 + 追击半径有限 → 绕行是合法策略，但宝箱常常在敌人身后——风险自选。
- 存档无感：进图自动存，从不担心进度。

## 3. 系统机制详述

### 3.1 地图规格总表（场景共 5 个 + 2 室内内嵌）
> 勘误声明：概念文档"共约 4 张地图"修正为 **5 个地图场景**（小镇/道路/遗迹三层）。工时仍在 18h 预算内，依据：① 室内不建独立场景——**内嵌到小镇 tilemap 的远角**（门=teleport 到同图远角房间，相机限区），零额外场景与存档状态；② 遗迹三层共用一套遗迹 tileset 与结构模板。

| 图 | 尺寸(tile) | 功能 | NPC | 宝箱 | 调查点 | 敌人 |
|---|---|---|---|---|---|---|
| 小镇 town | 64×48 + 内嵌 2 室内(12×9) | 剧情起点、存档点(客栈)、休整 | 12(6 有阶段对话) | 1 | 6 | 0 |
| 道路 road | 48×64 | 唯一通道，B1/B2 | 0 | 2 | 3 | 3（巡逻） |
| 遗迹 f1 | 56×44 | B3、教学探索 | 0 | 3 | 4 | 2（巡逻+追击） |
| 遗迹 f2 | 48×48 | B4 精英、队员聊天点 | 0 | 2 | 3 | 1 精英（定守） |
| 遗迹 f3 | 40×40 | Boss 前厅、补给 | 0 | 1 | 2 | 0（Boss 事件触发） |

合计：宝箱 9 / 调查点 18 / 敌人编组 4（对应战斗 GDD B1-B4，Boss 走事件）。
**密度校验**（玩家移速 4.5 tile/s）：小镇主街环线 ~90s，遇 12 NPC+6 调查+1 宝箱 ≈ 每 20s 一发现 ✅；道路蜿蜒路线 ~60s，遇 2+3+3=8 点 ≈ 每 8s（首图刻意加密）✅；f1 主路径 ~45s，遇 5+2 点 ≈ 每 9s ✅；f2/f3 前厅区密度减半、以强敌压迫替代发现密度（节奏性收窄，避免疲劳）——这是**有意设计** ✅。

### 3.2 可见敌人行为（三态，无寻路）
- **巡逻**：waypoint 循环或往返（路径在场景内以节点序列定义），恒速 2 tile/s。
- **追击**：玩家进入 **4 tile 半径**且敌人面朝方向 ±90°（伪视野，不设视线射线）→ 直线朝玩家移动（速 3 tile/s）；被墙卡住 1.5s 或玩家拉开 **6 tile** → 放弃，返回巡逻。**无寻路算法**——被墙挡住就卡住是可接受行为（遗迹地形以开阔厅+窄走廊为主，卡墙概率低且"甩掉敌人"本身就是乐趣）。
- **定守**：B4 精英（遗像守卫）与 Boss 不移动，站位即交战位（主题契合+保证关键战斗必打）。
- **接触判定**：双方碰撞盒相触 → A5 载荷发 `enemy_touched`。敌人不复活：胜利 → `defeat_enemy_uid` 写入 `cleared_enemy_set` 并**立即自动存档**（防"打赢→退出→重进→复活"）；逃跑 → 敌人保留原地。
- **战后回置保护**（工程已确认）：BattleResult 返回后玩家带 0.5s `encounter_immunity` 计时器；回置点生成规则优先取"敌人碰撞体反向外侧一格"，无敌只是兜底。

### 3.3 交互规范
- **交互键**：Z 或 E 均有效；检测范围 = 玩家面前 1 格 + 自身所在格。
- **调查 flavor**：调查点 = 交互触发器 + dialogue（`map_<map>_flavor.json` 单条目）；文案原则：一半给世界观氛围（"石像的眼睛被人凿去了"），一半给纯趣味（"花坛里的土最近被翻过"）。
- **宝箱开启** = 事件模板：`conditions:{not_flag:chest_id}` → `play_sfx + give_item + dialogue(获得提示) + set_flag`。开启状态走存档 schema 的 `chests_opened[]`（对齐 ADR-3，不用泛化 flags）。

### 3.4 地图切换与进图自动存档
- **传送点**：地图边缘/门口放 `trigger_teleport`（踩踏），事件 `{"type":"teleport","map":"road","spawn":"from_town"}`。小镇室内 = 同图远角 teleport。
- **进图自动存档精确时机（回签 I3 核心）**：**过传送点存，不进图即存**。精确序列：teleport 动作 → Router 载入新图 → 新图 `_ready` 完成且玩家落位到 spawn 点 → 地图侧广播 `map_ready` → `SaveManager.save()`。理由：teleport 完成态 = "站在新图入口"，恰是失败读档想要的恢复点；进图即存则可能存到转场中间态。
- 出生点安全：每个 spawn 点周围 8 格内无敌人初始位、无碰撞（制作校验项）。
- 首次启动（无存档）：开场剧情（P0）结束处执行一次 `save_point` 作为最初的存档。
- **存档原子写**（工程已确认）：写临时文件后 rename 替换，失败保留旧档；验收项"写入中途强杀进程，旧档可正常读出"。

## 4. UI/呈现需求
探索侧 UI 极简：仅交互提示角标（面前可交互时显示"!"气泡，0.2s 淡入）+ 存档图标（自动存档时右下角闪现 0.5s）。无 HUD 常驻项（HP 查看走主菜单）。接 UI 布局规格确认。

## 5. 数据结构需求
- 地图场景侧：每敌人节点 `enemy_uid, group_id, 巡逻 waypoints`；每传送点 `event_id`。
- GameData：`cleared_enemy_set`、`chests_opened`（均已入 ADR-3）。无其他新字段。

## 6. 边缘情况（4 条）
1. 追击敌人与巡逻路径互穿：敌人间无碰撞（互相穿过），仅与玩家/地形碰撞。
2. 战斗胜利回置点（return_position）恰在另一敌人碰撞范围内：战斗侧回置后 0.5s 无敌接触判定，玩家可走开。
3. 事件中战斗（Boss）失败读档：恢复到进图存档点，事件中断不残留（phase 未被 set，事件从头可再触发）。
4. 玩家在自动存档瞬间关游戏：save.json 写入为原子替换（工程侧义务，已确认）。

## 7. done 标准
- [ ] 5 图 + 2 内嵌室内完成，密度总表数值达标并实测走图验证
- [ ] 敌人三态行为正确；胜利移除+自动存档、逃跑保留，均实测
- [ ] 传送网络 12 处全通，每处 spawn 落位正确
- [ ] 进图自动存档按 3.4 时序生效；断电模拟（任务管理器杀进程）后从入口恢复
- [ ] 宝箱 9 / 调查 18 全部可交互且状态入存档
- [ ] 工时：地图制作 10h + 移动/碰撞/相机 2h + 传送 1.5h + 敌人 AI 3h + 交互 2h + 存档对接 2h + buffer 1.5h = **22h 卡满**

# 接口回签 I1-I5（本 GDD 部分）

| 接口 | 提供什么 | 消费什么 | 谁在何时调用 |
|---|---|---|---|
| **I1 遇敌触发** | 地图侧提供：接触检测→组装 BattlePayload(enemy_group_id/return_map/return_position/defeat_enemy_uid)→`enemy_touched` | 战斗侧消费 payload | 地图在碰撞回调时发；战斗在转场黑屏后读取 |
| **I2 探索奖励** | 双方共用 items 表；战斗掉落与宝箱 give_item 走同一 GameData 写入口 | 探索消费 BattleResult.items_gained 弹结算 | 胜利结算时战斗侧写；宝箱开启时事件写 |
| **I3 自动存档** | 探索侧义务：① teleport 完成后（map_ready 信号）存档；② 战斗胜利回图后立即存档；③ P0 开场末首次存档。战斗侧义务：失败读档时调用读档 | SaveManager 按 ADR-3 schema 存全部状态字段 | 存：上述三时机自动触发；读：失败流程与手动菜单 |
| **I4 升级系统** | 战斗侧义务：结算把 exp/party_state 写回 GameData（含升级与技能习得） | 探索/对话侧零感知，读 GameData 即可 | battle_finished 载荷回写时 |
| **I5 Boss 事件锚点** | 约定事件 id：`story_boss_pre`（战前台词→`battle{group:boss_core}`→胜利续行→战后台词→`set_story_phase(3)`→`save_point`，战后内容并入同一事件一次触发避免中途态）；Boss 敌人本体不放地图，由该事件的 battle 动作召唤 | 对话系统执行 dialogue；战斗系统执行 battle 动作并回传 outcome | f3 Boss 触发器（交互键，非踩踏——给玩家"我准备好再开"的主动权） |

**phase 切换点最终汇总**：`story_quest_accept` 末尾 0→1；`story_ruin_enter` 末尾 1→2；`story_boss_pre`（战后段）内 2→3。三处均为 `set_story_phase` 动作。

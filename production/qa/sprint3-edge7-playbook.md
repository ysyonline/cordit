## 边缘 1 · 队列中某单位在轮到它之前死亡

**GDD 原文（§3.6 之 1）**：队列中某单位在轮到它之前死亡：跳过其行动，队列即刻重算预告条。

### 语义拆解（三条独立断言，缺一不可）
1. **跳过**：死者不执行行动，不产生任何结算
2. **队列重算**：死者从队列移除（不是"标记 dead 但保留槽位"）
3. **预告条立即刷新**：这是"即刻"二字的落点，也是玩家唯一能感知的通道

### 构造法

**前置数据**
- 敌方 3 只：E1(SPD 10, HP 20) / E2(SPD 9, HP 20) / E3(SPD 8, HP 20)
- 我方：凯尔 SPD 12 / 莫娜 SPD 11 / 莉娜 SPD 10
- 队列（SPD 降序）：凯尔(12) → 莫娜(11) → 莉娜(10, 同 SPD 我方恒前于敌方) → E1(10) → E2(9) → E3(8)

**触发步骤**
1. 凯尔行动：用**群体技能「横扫」**（敌群 ×0.9）或莉娜「雷爆」（敌群雷 ×1.0）一次性打死 E2（SPD 9，尚未行动）
2. 观察队列与预告条

### 断言点

| # | 断言 | 层 | 可自动化 |
|---|---|---|---|
| 1.1 | 队列重算后**不含** E2（`assert_false(queue.has(E2))`） | L1 | ✅ |
| 1.2 | 队列长度 == 5（原 6 − 1） | L1 | ✅ |
| 1.3 | 预告条 3 格**不含** E2 的头像/标识 | L2 | ✅ |
| 1.4 | E2 不产生任何结算（我方 HP/MP 不变，无 `battle_finished`） | L2 | ✅ |
| 1.5 | 刷新发生在**结算当帧**，不是下一轮开始才更新 | L2 | ✅ |
| 1.6 | 预告条视觉上确实变了（截图/录屏前后的 3 格内容不同） | L3 | ❌ 人眼 |

### ⚠ 常见错误实现（本条的测试价值所在）
- **"懒删除"**：内部标记 `is_dead = true` 但保留槽位，行动时 `continue` 跳过。后果：队列长度不变、预告条**仍显示死者**——玩家看到"下一个是它"，但它永远不会动。断言 1.2 / 1.3 专抓这个。
- **延迟重算**：等到本轮结束才重建队列。后果：预告条本轮内一直显示死者。断言 1.5 专抓这个。

## 边缘 2 · 当前行动者被"掩护"目标转移伤害致死

**GDD 原文（§3.6 之 2）**：当前行动者被"掩护"目标转移伤害致死：由掩护者承接，不中断行动结算。

### 语义拆解
1. **转移**：伤害打到掩护者身上，不是原目标
2. **致死也承接**：即便这一下会打死掩护者，也照承不误
3. **不中断**：行动结算流程继续走完，不抛错、不空转、不提前进入失败流程

### 构造法

**前置数据**
- 凯尔对莫娜使用「掩护」（4 MP，我方单体，本回合代替目标承受其受到的所有伤害，自身承伤 ×0.5）
- 莫娜 HP 设为**极低**（如 5），凯尔 HP 设为中等（如 60）
- 敌方单次伤害设为**必杀莫娜但打不死凯尔的一半**（如 30 → 莫娜 5 必死，凯尔承 30×0.5 = 15 < 60 不死）

**触发步骤（两个变体，都要跑）**
- **变体 A（掩护者不死）**：敌方攻击莫娜 → 伤害转移到凯尔（×0.5 = 15）→ 莫娜存活
- **变体 B（掩护者被打死）**：把凯尔 HP 调到 10 → 承伤 15 致死 → 验证"不中断行动结算"

### 断言点

| # | 断言 | 层 | 可自动化 |
|---|---|---|---|
| 2.1 | 变体 A：莫娜 HP **不变**（伤害未打到她） | L1 | ✅ |
| 2.2 | 变体 A：凯尔 HP == 60 − 15 == 45（**×0.5 生效**） | L1 | ✅ |
| 2.3 | 变体 B：凯尔 HP 归 0，但**行动结算正常返回**（函数不抛错、不空转） | L1/L2 | ✅ |
| 2.4 | 变体 B：队列**正常推进**到下一个单位（不卡死、不重入） | L2 | ✅ |
| 2.5 | 掩护**与防御不叠加**：凯尔若同时处于防御状态，承伤仍为 ×0.5（不是 ×0.25） | L1 | ✅ |
| 2.6 | 掩护持续范围：仅本回合，下回合失效 | L2 | ✅ |
| 2.7 | 掩护者死亡后，UI 状态栏正确显示（不残留"掩护中"角标） | L3 | ❌ 人眼 |

### ⚠ 常见错误实现
- **转移后原目标仍扣血**（伤害打了两次，或先扣原目标再转移）
- **致死时"当前行动者没了"导致空指针**：结算函数里持有的是原目标引用，转移后引用未更新 → 崩或静默跳过。断言 2.3 专抓。
- **与防御叠乘**（×0.5 × 0.5 = ×0.25）——GDD §3.4 明文"与防御不叠加，掩护中视为防御姿态"。断言 2.5 专抓。

## 边缘 3 · 击退目标恰好只剩 1 个未行动槽位

**GDD 原文（§3.6 之 3）**：击退目标恰好只剩 1 个未行动槽位：击退按 2 槽计算但实际只后移至本轮末尾（不跨轮，见 3.1）。

### 语义拆解（本条最容易写错，也最值得自动化）
1. **按 2 槽计算，但 clamp 到本轮末尾**：不是"移动 1 槽"（因为只剩 1 个）、也不是"跨到下一轮首位"
2. **不跨轮**：击退后它仍在**当前轮**
3. **已行动部分不受影响**：击退只重排"未行动"区间

### 构造法

**前置数据**
- 队列 6 单位（SPD 降序）：凯尔(12) → 莫娜(11) → 莉娜(10) → E1(10) → E2(9) → E3(8)
- 推进到**莉娜行动**（此时已行动：凯尔、莫娜；未行动：莉娜、E1、E2、E3）
- 让 E2（当前排在未行动区第 2 位）成为击退目标
- 制造"只剩 1 个未行动槽位"的临界：把队列推进到 **E2 是未行动区倒数第 2 位**时触发击退，即击退后它后面**只剩 1 个**单位（E3）

**触发步骤**
1. 推进队列到 E1 行动之前 / 或直接构造队列状态：已行动 = [凯尔, 莫娜, 莉娜, E1]，未行动 = [E2, E3]
2. E1 或我方对 E2 造成**弱点属性命中**（触发击退）
3. 观察 E2 的新位置

### 断言点

| # | 断言 | 层 | 可自动化 |
|---|---|---|---|
| 3.1 | 击退后 E2 位于**当前轮的最后一位** | L1 | ✅ |
| 3.2 | E2 **仍在当前轮**（断言其所在轮次标识 == 当前轮） | L1 | ✅ |
| 3.3 | **已行动区间完全不变**：[凯尔, 莫娜, 莉娜, E1] 顺序与内容不变 | L1 | ✅ |
| 3.4 | 队列总长度不变（击退不是删除） | L1 | ✅ |
| 3.5 | 预告条立即刷新，E2 从预告位置消失、E3 前移 | L2 | ✅ |
| 3.6 | **边界对照**：若 E2 已是未行动区最后一位时再击退，位置**不变**（无处可退） | L1 | ✅ |
| 3.7 | 本轮结束后重置，E2 回到按 SPD 的正常序位（击退不残留到下一轮） | L1 | ✅ |

### ⚠ 常见错误实现
- **用 swap 两次实现"移动 2 槽"**：在边界处会把已行动的单位换到未行动区，或把 E2 换出本轮。断言 3.3 专抓。
- **`index += 2` 不 clamp**：越界后要么崩、要么把 E2 塞进下一轮首位（违反"不跨轮"）。断言 3.2 专抓。
- **击退残留**：E2 下一轮起始位被惩罚。GDD §3.1 明文"若已行动过，则下一轮起始位惩罚无效化"。断言 3.7 专抓。

## 边缘 4 · MP 不足时技能菜单全部置灰（防软锁）

**GDD 原文（§3.6 之 4）**：MP 不足时技能菜单全部置灰：防御/道具/攻击必须永远可用，防止软锁。

### 语义拆解
1. MP 不足 → 技能项置灰（可灰，允许）
2. **攻击 / 防御永远可用**（不可灰）
3. **道具**：背包有可用道具 → 可用；背包空 → 可灰，但**必须能取消返回**
4. **系统级不变量**：不存在"四个指令全灰"的状态

> 本条是**唯一一条直接防软锁**的边缘情况，也是 7 条里最该硬断言的一条。玩家一旦卡在"所有指令都灰"的状态，整场战斗永久卡死——这是 Blocker 级。

### 构造法

**四种前置组合，全部要跑（2×2 矩阵）**

| 组合 | MP | 背包 |
|---|---|---|
| A | 0（全队三人均为 0） | 空 |
| B | 0 | 有可用道具（回复 HP） |
| C | 1（不够最便宜技能的 3 MP） | 空 |
| D | 足够 | 空（对照：技能应可用） |

**触发步骤**
1. 设置对应前置
2. 进入指令菜单
3. 逐项检查 `disabled` 标志
4. 选「道具」→ 观察提示 → 按取消 → 观察状态回退

### 断言点

| # | 断言 | 层 | 可自动化 |
|---|---|---|---|
| 4.1 | 组合 A/C：**攻击** `disabled == false` | L2 | ✅ |
| 4.2 | 组合 A/C：**防御** `disabled == false` | L2 | ✅ |
| 4.3 | 组合 A/C：所有技能项 `disabled == true` | L2 | ✅ |
| 4.4 | 组合 B：**道具** `disabled == false` | L2 | ✅ |
| 4.5 | 组合 A：**道具** `disabled == true`，但**可取消返回**菜单 | L2 | ✅ |
| 4.6 | **不变量断言（最重要）**：四种组合下，`(攻击可用 or 防御可用)` 恒为 true —— 不存在四指令全灰 | L2 | ✅ |
| 4.7 | 组合 D（对照）：技能可用，MP 扣减后若不足则下一回合置灰 | L2 | ✅ |
| 4.8 | 人眼：置灰项视觉可辨识（不是"变淡到看不出"） | L3 | ❌ 人眼 |

### ⚠ 常见错误实现
- **统一"资源不足即禁用"的写法**波及攻击/防御 → 直接软锁。断言 4.6 是专为此设的**不变量断言**，建议作为独立 test 函数长期保留，即使其他用例被砍。
- **道具禁用后取消键也被吞**：玩家进了道具菜单出不来。断言 4.5 专抓。

## 边缘 5 · 道具耗尽

**GDD 原文（§3.6 之 5）**：道具耗尽：道具菜单显示"背包中无可用道具"，指令可取消返回。

### 语义拆解
1. **提示**：显示明确的空态文案（不是空白列表、不是静默无反应）
2. **可取消返回**：状态机回退到指令菜单，无残留
3. **不消耗回合**：打开空道具菜单再取消，**不应消耗该角色回合**（由题意"指令可取消返回"推得——若消耗回合则是惩罚性设计，GDD 未授权）

### 构造法

**前置数据**
- `GameData.inventory = {}`（空背包）
- 角色处于指令菜单

**触发步骤**
1. 选「道具」→ 观察提示与列表
2. 按取消 → 观察回退
3. **变体**：背包内只有**不可用阶段**的道具（GDD §5 道具表有 `可用阶段(地图/战斗/皆可)` 字段）→ 战斗内应视为"无可用道具"

### 断言点

| # | 断言 | 层 | 可自动化 |
|---|---|---|---|
| 5.1 | 显示提示文本，含"无可用道具"语义（断言文本存在 + 非空） | L2 | ✅ |
| 5.2 | 列表为空（0 个可选项） | L2 | ✅ |
| 5.3 | 按取消 → 回到指令菜单（状态机回退正确） | L2 | ✅ |
| 5.4 | 取消后**该角色回合未被消耗**（仍在指令菜单，队列未推进） | L2 | ✅ |
| 5.5 | 变体：只有"仅地图可用"的道具时，同样显示无可用道具 | L2 | ✅ |
| 5.6 | 无异常抛出、无空指针（空列表上的光标移动不炸） | L2 | ✅ |
| 5.7 | 人眼：提示文案可读、不越出 640×360 | L3 | ❌ 人眼 |

### ⚠ 常见错误实现
- **空列表上光标越界**：光标尝试聚焦第 0 项 → 崩。断言 5.6 专抓。
- **忘记过滤"可用阶段"**：把只能地图用的道具列进战斗菜单，选了没反应。断言 5.5 专抓。

## 边缘 6 · 敌人被击退后、行动前死亡

**GDD 原文（§3.6 之 6）**：敌人被击退后、行动前死亡：从队列移除，其被跳过不产生任何结算。

### 语义拆解
1. **时序**：先被击退到本轮末尾 → 在轮到它之前死亡
2. **移除**（不是标记）
3. **不产生任何结算**：轮到它的位置时，不执行攻击、不触发 AI、不抛错
4. 本条是**边缘 1 与边缘 3 的组合时序**，最容易在"击退后的位置管理"上出 bug

### 构造法

**前置数据**
- 队列：凯尔(12) → 莫娜(11) → 莉娜(10) → E1(10) → E2(9) → E3(8)
- 给 E2 施加**中毒**（GDD §3.6：中毒每回合**行动前**扣 最大HP×5%，持续 3 回合）——这是构造"行动前死亡"最自然的手段
- E2 HP 设为恰好：击退后到它行动前，中毒扣血足以致死（如 E2 HP = 3，最大 HP 20 → 中毒每回合扣 1… 需按实际公式调；或直接把 HP 设为 1）

**触发步骤（两条路径都要跑）**
- **路径 A（中毒致死）**：凯尔弱点命中 E2（触发击退，E2 后移至本轮末尾）→ 推进队列 → E2 行动前中毒结算致死
- **路径 B（直接击杀）**：击退 E2 后，在其行动前用另一次攻击/AOE 打死它

### 断言点

| # | 断言 | 层 | 可自动化 |
|---|---|---|---|
| 6.1 | 路径 A：中毒在**行动前**结算（扣血发生在 E2 执行攻击之前） | L1 | ✅ |
| 6.2 | E2 死亡后**从队列移除**（`assert_false(queue.has(E2))`） | L1 | ✅ |
| 6.3 | 队列长度 −1 | L1 | ✅ |
| 6.4 | **不产生任何结算**：我方 HP/MP 在 E2 的原槽位上无变化 | L2 | ✅ |
| 6.5 | 无异常抛出（队列遍历中删除元素的安全性） | L2 | ✅ |
| 6.6 | 预告条同步刷新，不含 E2 | L2 | ✅ |
| 6.7 | 路径 B（直接击杀）结果与路径 A 一致 | L2 | ✅ |

### ⚠ 常见错误实现
- **遍历中删除导致跳过一个单位**：`for i in queue.size()` 里 `queue.remove_at(i)` → 索引错位，下一个单位被跳过。断言 6.4 + 6.3 专抓。
- **击退后的位置索引失效**：击退存的是旧索引，死亡删除后旧索引指向错误的单位。需要断言"击退记录与队列同步失效"。
- **中毒结算时机错**（行动后而非行动前）→ 本条永远构造不出来，反而掩盖 bug。断言 6.1 专抓。

## 边缘 7 · 我方全灭发生在敌人行动结算途中

**GDD 原文（§3.6 之 7）**：我方全灭发生在敌人行动结算途中：立即中断剩余敌方行动，直接进入失败流程。

### 语义拆解
1. **结算途中**：典型场景是敌方**群体攻击**（多目标循环），在循环打到第 2/3 个角色时全灭
2. **立即中断**：循环内剩下的目标不再结算
3. **直接进失败流程**：`battle_finished(DEFEAT)` 发出，**且只发一次**
4. **剩余敌方行动全部取消**：队列里后面还没行动的其他敌人也不再行动

> 本条是 7 条中**唯一涉及"中断 + 去重"**的，也是最容易出"失败流程触发两次"这类隐蔽 bug 的地方。

### 构造法

**前置数据**
- 我方三人 HP 全部设为**低值**（凯尔 5 / 莉娜 5 / 莫娜 5）
- 敌方编组 ≥2 只，其中当前行动者使用**群体攻击**（B4 守卫 AI 的"群击"权重 15，或直接用调试构造）
- 群体伤害足以一击打死全部三人
- 队列后面仍有 ≥1 只未行动的敌人（验证"剩余敌方行动被取消"）

**触发步骤**
1. 推进到敌方群体攻击结算
2. 循环打到第 1 个角色即已全灭（或打到第 2 个时全灭，两种时序都测）
3. 观察：剩余目标是否继续结算、后续敌人是否继续行动、失败流程触发次数

### 断言点

| # | 断言 | 层 | 可自动化 |
|---|---|---|---|
| 7.1 | 全灭瞬间**立即**进入失败流程（不等待本轮/本轮内剩余结算完成） | L2 | ✅ |
| 7.2 | **剩余目标不再结算**：断言全灭后我方 HP 不再变化（无人被"打第二次"） | L2 | ✅ |
| 7.3 | **后续敌方行动全部取消**：队列里未行动的敌人不执行任何结算 | L2 | ✅ |
| 7.4 | **`battle_finished` 只发一次**（用 `watch_signals` + `assert_signal_emit_count`，GUT 原生支持） | L2 | ✅ |
| 7.5 | outcome == "DEFEAT"，payload 结构与 A5 BattleResult 协议一致 | L2 | ✅ |
| 7.6 | 不再弹出任何指令菜单（状态机已退出战斗态） | L2 | ✅ |
| 7.7 | 无异常抛出（中断路径上的资源清理安全） | L2 | ✅ |
| 7.8 | 人眼：失败画面（"残响中断"）正确呈现，读档占位提示可见 | L3 | ❌ 人眼（视频 #3 分镜 8） |

### ⚠ 常见错误实现
- **循环不 break**：群体攻击继续打完剩下两个目标（虽然都死了，但会触发额外的死亡结算/信号）。断言 7.2 专抓。
- **失败流程触发两次**：AOE 循环里每个目标死亡都检查一次全灭 → `battle_finished` 发 3 次 → E2-S4 写回闭环执行 3 次。断言 7.4 是**去重断言**，本条最关键。
- **只中断当前敌人，不取消后续敌人**：队列继续推进，其他敌人还在打。断言 7.3 专抓。
- **中断后状态机残留**：战斗结束了但指令菜单还在等输入。断言 7.6 专抓。

## 1. 版本号定义（建议：`v0.1.0-slice`）

### 1.1 结论

**对外版本号：`v0.1.0-slice`**
**内部里程碑标签：`m7`（沿用 m1–m6 序列，照 `production/README.md` §3/§5 纪律打）**

两者并存、不冲突：`m7` 回答"第几个里程碑"，`v0.1.0-slice` 回答"对外这是第几个可玩版本"。

### 1.2 为什么不是 v1.0

1.0 在 SemVer 与玩家心智里都等于"功能完整的正式版"。这一版是**4 张地图 + 5 场战斗 + 一条主线**的 30 分钟切片：无音效（`assets/sfx/` 为空，`chest_open.ogg` 路径悬空）、无设置菜单、无多语言、无窗口/音量选项、敌人与角色均为占位色块、单存档槽。叫 1.0 会让作品集评审按"完整游戏"标准衡量，反而扣分。

### 1.3 为什么不是 v0.0.x

0.0.x 通常指"跑不起来的内部原型"。这一版有明确的开头与结尾、可完整通关、有存读档、有可双击运行的 Windows 包——它是**第一个可被外人从头玩到尾的版本**，够得上 0.1.0。

### 1.4 为什么带 `-slice` 后缀

不带后缀的 `v0.1.0` 容易被读成"抢先体验版/试玩 Demo，后续会有完整版"。`-slice` 是给读者的一句话免责声明：**这就是交付物本身，不是成品的前哨**。作品集场景下这个区分很重要——评审看到的是"一个有头有尾的垂直切片"，不是"一个做了一半的游戏"。

### 1.5 备选方案与不推荐的理由

| 备选 | 不推荐理由 |
|---|---|
| `v1.0-slice` | 主版本号仍然宣称"完整"，与 `-slice` 自相矛盾 |
| 直接用 `m7` | 里程碑编号是内部排期语言，读者看不出"这是第几个可玩版本"，且下一个切片会变成 `m8`，版本号无法表达版本间关系 |
| `2026-09-05` 日期版 | 无版本间可比性，无法回答"这一版比上一版新在哪" |
| 不打版本号 | 试玩者反馈将无法归因到具体版本（"你玩的是哪一版？"），M7 之后的任何修复都失去参照系 |

### 2.1 关于 exe/pck 成对约束（分发时的硬约束）

`export_presets.cfg` 中 `binary_format/embed_pck=false` —— pck **未嵌入** exe。因此：

- 两个文件**必须同目录、主文件名一致**（`轨迹残响.exe` + `轨迹残响.pck`），缺其一则启动失败。
- 打包 zip 时必须两个一起打，且**保留中文文件名**（改名会破坏匹配关系，除非同时改两个文件的名字）。
- 若希望"单文件 exe 更好发"，可后续改 `embed_pck=true` 重导（体积相近，约 107 MiB）——但 100 MB 单文件对网盘/邮件并不比 zip 更友好，**建议保持现状**。

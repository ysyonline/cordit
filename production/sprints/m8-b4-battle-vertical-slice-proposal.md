## 二、现状盘点（先实证，后诊断）

### 2.1 架构分层与战斗流程

战斗为三层结构，分层纪律良好：

- **纯算法层** `scripts/core/battle_logic.gd`：RefCounted 纯函数，零 import、零随机 API（随机由调用方注入，`battle_logic.gd:14-17`）、公式系数集中在顶部常量块（`battle_logic.gd:51-108`，共 22 常量，每个标注 GDD 出处）。
- **编排层** `scripts/battle/battle_command.gd`：RefCounted 状态机——`setup/start`（`battle_command.gd:72-97`）构建首轮 SPD 队列；`submit_command`（`:260-305`）走"行动前中毒 tick → 执行指令 → 胜负检查 → 推进队列"四步；`enemy_action`（`:433-494`）处理敌方 AI 权重抽取、蓄力/释放、中毒附加；轮末 `_new_round` 重建队列并重置瞬时姿态（`:640-655`）；胜利结算器 `build_settlement`（`:684-743`，经验/掉落/升级/习得，无随机项）。
- **驱动与视图层** `scripts/battle/battle_scene.gd` + `battle_ui.gd`：场景装配队伍（GameData 现值、非满血开局，`battle_scene.gd:181-192`）、输入桥 `command_selected → submit_command`（`:109-120`）、敌方节拍驱动 `ENEMY_ACT_BEAT=0.9s`（`:62,125-141`）、结算驻留（揭示可跳过 + 15s 护栏 + 出战黑屏，`:148-170`）。
- **写回闭环** `battle_result_handler.gd`：party_state 覆写 / 掉落入包 / 胜利登记击破 / DEFEAT 自动读档 / 回图回置+0.5s 免疫（`battle_result_handler.gd:66-121,183-233`）。

### 2.2 指令系统

五指令 attack/skill/item/defend/escape（`battle_command.gd:22-26`）；可用性由 `available_commands` 决定——攻击/防御永远可用防软锁，B1 编组 `skills_locked` 锁技能、Boss 编组 `escape_forbidden` 禁逃跑、空背包道具置灰（`battle_command.gd:143-151`）；目标合法性 `targets_for`（`:186-212`）；单体技能/治疗只结算玩家选中 target_slot（D3 修复口径，`:232-250`）；防御 ×0.5 且回 5 MP（`battle_logic.gd:457-463`）；逃跑检定随机外部化，roll<0 时缺省 `randf()`（`battle_command.gd:417-424`）。

### 2.3 数值模型（口径核对）

- 物理 `max(1, ATK×2 − DEF×1.0)×倍率×浮动`、法术 `max(1, MAG×2.2 − DEF×1.2)×倍率×属性倍率×浮动`（`battle_logic.gd:74-78,363-381`）——与已裁决口径（物理 DEF 系数 1.0 / 法术 1.2）一致。
- 浮动 0.9~1.1 由 `variance_from_roll(randf())` 注入，生产链两处：玩家指令 `battle_scene.gd:118`、敌方行动 `battle_scene.gd:138`。
- 回复不吃浮动与 DEF（`battle_logic.gd:405-406`）；中毒 5% maxHP/回合、3 回合、时长可叠（`battle_logic.gd:99-100,438-441`）。
- 结算：gold 恒 0（`battle_command.gd:777`）；战斗间 HP/MP 不回满——战斗单位取 GameData 现值、写回保持现值（`battle_scene.gd:189-190`、`battle_command.gd:767-770`）；切片内无回复点，与已裁决口径一致。

### 2.5 UI 元素

八要素 HUD 齐（`battle_ui.gd:165-263`）：行动预告条 3 格（§4.1）/ 指令菜单五按钮（§4.2）/ 我方状态卡×3 含 HP/MP 条与中毒角标（§4.3）/ 敌方 HP 条受击显示 3s 淡出（§4.4）/ 目标光标+预估伤害区间"— 24~29 —"（§4.5，复用 BattleLogic 真值防漂移 `:636-655`）/ 浮动数字层（§4.6）/ 结算面板（§4.7）/ 背景（§4.8 占位）。键盘只覆盖目标选择态与结算跳过（`_unhandled_input`，`battle_ui.gd:804-825`）；指令菜单为鼠标 Button，无焦点管理。

### 2.6 测试覆盖

GUT 574/574 全绿。战斗相关 13 个测试文件引用战斗符号，重心分布：纯函数层最厚（`test_e3s2.gd` 249 处引用）、编排层次之（`test_e3s3.gd` 17 处）、生产驱动链有专测（`test_o6_real_battle.gd`、`test_o7_ui_bridge.gd` 含键盘目标选择/防越权/驻留转发）。**盲区**：演出层断言多为"节点存在性"（`battle_ui.gd:975-1027` 的 `has_*`/`get_*` 查询接口即为此设计），无时序性/观感性断言——这正是 O-7 缺陷（UI 信号无人消费）曾漏测的同一类盲区的演出层版本。

### 2.7 口径核对发现（需主理人确认）

- **逃跑公式不一致**：任务简报口径为"逃跑 80%×3 次"；但 GDD §3.5（`battle-system-gdd.md:147`）与代码（`battle_logic.gd:105-108,494-502`：70% + SPD差×2%，钳 30%~95%，每角色各自可尝试）均为另一公式。简报口径未见于仓库任何文档——**未确认（原因：正本 GDD 与代码同口径，简报"80%×3 次"无出处；可能是简报笔误或未落档的新裁决）**。本提案不改任何一方，仅提请裁决。
- `randomize()` 未在战斗链调用（`battle_scene.gd:118,138` 直接 `randf()`）——每局进程内随机序列是否需要播种种子的可复现性，属 QA 诉求，非缺陷，不展开。

## 四、垂直切片目标与成功标准

**一句话目标**：让玩家在 B1-B5 任意一场战斗中，每一拍都看得到"谁在行动、谁挨了多少、敌人要放大招了、谁倒下了"——战斗从"可玩的数值"变成"可读的演出"。

**垂直切片边界声明**：本切片**不是**补全战斗系统（不做新指令、新技能、新机制、新数值），**而是**把既有已冻结的机制全部"让玩家看见/听见"。机制层零改动，是本提案与未来战斗扩展立项的根本区别。

**可验收的成功标准**：

1. **蓄力可读**：B5 Boss 蓄力回合，玩家在敌人行动前能看到持续存在的预警标识；3 次人工测试中 3 次能用防御/掩护把释放承伤减半。
2. **归因可读**：任意一回合结束后，观察者仅凭画面能正确复述本回合行动序列与每次伤害的归属（对照战斗日志，5 回合抽测无错）。
3. **零残留**：一场 10+ 回合战斗结束后，浮层上无任何残留数字/弹字（自动断言：战斗结束 `_float_layer` 子节点数归零）。
4. **形象在场**：敌我双方均有可视形象；每次攻击有可辨识的出手表现（位移或受击反馈至少其一）。
5. **不破坏既有**：GUT 全量绿（574+新增）；`battle_logic.gd` 系数块 diff 为零；存档协议（ADR-3）与数据表（ADR-2）零改动。

## 五、方案选项 A / B / C

> 工时口径：1 卡 = ≤半天（小卡纪律）；用户投入 5-10h/周，卡数×0.5d÷(5~10h/周) ≈ 周数区间。
> 共同红线：三方案均不触碰 `battle_logic.gd`、不动 .tres 数值、不动存档协议、不加 Autoload。

### 方案 A · 可读性补丁 ——「先让现有战斗能被读懂」

- **做什么**：修 D1-D7 全部（3×P0 中的可无资产部分 + 全部 P1）：charge/charge_release 警示横幅与持续角标；浮动数字上飘+淡出+自动回收；闪白仅我方受击触发；死亡呈现（我方卡灰化、敌方条隐藏）；escape_fail/success 提示；结算面板溢出防御（D10 顺手修）。
- **不做什么**：不加精灵、不加动画位移、不加音频、不动敌方 AI（D12）、不做键盘导航（D8）。
- **涉及文件模块**：仅 `scripts/battle/battle_ui.gd`、`battle_hit_feedback.gd`、（横幅新建小控件可入同目录）；测试 `tests/gut/` 补断言。**零场景 .tscn 改动**。
- **工作量（6 卡）**：
  - A1 charge 警示横幅+释放提示（0.5d）
  - A2 浮动数字动画化+回收（0.5d）
  - A3 闪白分敌我（0.5d）
  - A4 死亡呈现（0.5d）
  - A5 逃跑/事件最小反馈+结算溢出防御（0.5d）
  - A6 GUT 补断言+全量回归（0.5d）
- **风险与回滚**：低。全部纯视图层；模型层零触碰；每卡独立可 revert，最坏情况单卡回滚不影响他卡。
- **对 ADR 影响**：ADR-1 渐进类型照旧（preload 常量、无 class_name）；ADR-2/3 零触碰；ADR-4 无新纹理，仅既有 ColorRect/Label 动画，无整像素风险。
- **做完后的终态**：D1-D7、D10 清零。战斗"信息可读"但仍"无人无声"——P0 的 D2/D3 只解决了一半。

### 方案 B · 呈现层垂直切片 ——「让战斗看起来像一场战斗」（**主推荐**）

- **做什么**：A 全部 + D2 攻坚：敌我战斗形象与最小演出。我方接入现有 charsets（`assets/characters/charsets_12_m-f_*.png`，antifarea 包已入库有 CC 授权，见 `assets/licenses/notices/antifarea-sprites.txt`）切 idle 帧；敌人用与地图 `visible_enemy` 同风格的占位形象（BodyRect 暗红块升级为带轮廓的占位精灵）；入场两侧走入 + 攻击 lunge + 受击抖动 + 死亡淡出；目标光标/浮动数字/闪白落点从"HP 条坐标"迁移到"精灵坐标"。
- **不做什么**：不加音频（D3 留给 C）、不动敌方 AI、不做新机制。
- **涉及文件模块**：A 的全部 + `battle_ui.gd` 布局层大改（新增 Sprite 层，`_target_screen_pos`/`_event_screen_pos` 迁移 `battle_ui.gd:536-542,960-966`）；可能新增 `battle_stage.gd`（站位/演出编排纯视图层）；测试补演出现场断言。
- **工作量（13 卡 = A6 + B7）**：
  - B1 战斗站位骨架：敌我 Sprite 槽位布局（640×360 内我方左/敌方右），入场走入（0.5d）
  - B2 我方精灵接入：charsets 切图 + idle 帧 + AssetMapper 式映射（0.5d）

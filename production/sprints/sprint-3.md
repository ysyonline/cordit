## 1. Sprint 目标（Sprint 结束 = 里程碑门 M3 通过）

**一句话**：E2 的占位胜负按钮被真战斗逻辑取代——速度队列 + 三系克制 + 四指令 + 战斗 UI 全套成型，B1/B2 两场战斗可完整游玩。

**DoD（Lean 口径，沿用 M1/M2）**：
1. EPIC-3 六条 Story 验收标准逐条勾绿（`production/epics/EPIC-3.md` 原文为准）。
2. GUT 全量回归无回归（E2-S1~S4 的 62 用例 + E3 新增用例全绿，evidence/ 留档）。
3. B1（道路飞蛾）+ B2（雷壳甲虫）两场战斗可完整游玩（三问测试口径）。

## 4. 风险与缓解

| # | 风险 | 概率 | 缓解 |
|---|---|---|---|
| R1 | 30h 是切片最重 Epic，纯函数 + UI 双线，超支风险高 | 高 | buffer 3h 兜底 + EPIC-3.md 砍序（S5 打磨→S4 预估伤害→S3 逃跑完善；队列/克制/四指令/UI 骨架不可砍） |
| R2 | battle_logic 必须无 get_node（A1 铁律 3），测试覆盖不足致平衡调校痛苦 | 中 | S2 全纯函数 + GUT 单测，同配置战斗顺序可复现（§3.1 不引入随机），克制三档 ×1.5/×1.0/×0.5 单测硬断言 |
| R3 | 数值平衡 12h 是独立条目，M3 不含 B3-B5 全量调校 | 中 | M3 只验证 B1/B2 可玩；B3-B5 体感调校留打磨阶段，不在本 Sprint 超支做 |
| R4 | 战斗 UI 640×360 + 9-slice 边条平铺禁拉伸（ADR-4） | 低 | UI 布局规格 v1.1 已定 + 美术骨架（9-slice 窗体框全自制五色板两套）；S4 严格按规格，不临场改 |
| R5 | 失败读档依赖探索侧进图存档（GDD I3） | 低 | S3 此阶段允许占位提示（与 E2-S4 一致口径），真读档 E4-S7 接管，不阻塞 M3 |
| R6 | 跨战斗弱点记忆写入 GameData discovered_weakness_set 与存档 schema 冲突 | 低 | 字段已在 E1-S2 GameData 声明 + E2 验证过单例边界；S5 只写不改 schema |

## 5. 砍序（EPIC-3.md 第 59 行原文）

到 W6 末未收口时的砍序：**S5 打磨项 → S4 的预估伤害区间 → S3 的逃跑完善**；队列 / 克制 / 四指令 / UI 骨架不可砍。

## 6. Sprint 外并行（不占 30h 工时账）

- 数值平衡 12h（GDD §7，独立条目）——M3 后或打磨阶段做，B3-B5 每场实跑 2 遍调校。

## 1. Sprint 目标（Sprint 结束 = 里程碑门 M4 通过）

**一句话**：小镇之外的通往遗迹之路被补全——道路 + 遗迹三层可探索，可见敌人会追会放，宝箱/调查可交互且状态入档，进图自动存档 + 战败真读档闭环成型。

### M4 门条件（A8 行 4 四要素）

| 门要素（A8 行 4） | 覆盖 Story | 验证方式 |
|---|---|---|
| ① 三层遗迹可探索 | E4-S3（+S2 道路连接层） | town→road→f1→f2→f3 全程实测走图，三层纵向推进暗示成立 |

**DoD（Lean 口径，沿用 M1-M3）**：

- **目标**：EPIC-4 遗迹施工要克隆 town 工具链（gen → verify → tile-inspect），该管线当前是坏的，排期必须压在最前。
- **做什么**：
  1. 7 处硬编码绝对路径改仓库相对路径（或加 argparse）：`gen_town.py` 380/382、`verify_town.py` 11/12/13、`tile-inspect/analyze_tiles.py` 8、`tile-inspect/tile_ascii.py` 38；
  2. tile-inspect 两脚本指向的 `.rgba` 已迁至 `tools/tile-inspect/`，路径同步修正；
  3. 跑通 `tools/README.md` 五步调用顺序全链路作为验收证据（含 town 产物重跑 verify 回归 PASS）。
- **依赖**：无。**阻塞**：E4-S2、E4-S3（遗迹生成器/核验器克隆）。
- **验收口径**：`tools/README.md` 已知缺陷表清零；5 步全链路可复跑，退出码 0。
- **测试要求**：不新增 GUT（Python 工具非运行时依赖）；以"verify_town 重跑全 PASS"作为回归证据留档。
- **处置建议**：tile-inspect 两脚本按 tool-disposition 裁决表**修路径保留**（遗迹图集选型要复用），不建议归档——理由已录 tool-disposition §2"工具组四件同进退"。

### E4-S1 SaveManager 完整实现 · 3.5h
- **目标**：`autoload/save_manager.gd` 从 E1-S2 空壳（当前仅 SCHEMA 常量，零 IO）变成真存读档：schema 全字段 + 读档回灌 GameData + 原子写 + version 迁移骨架。
- **依赖**：无（数据侧地基，可最先与 S0 并行）。**被依赖**：S5（chests_opened 入档）、S6（自动存档）、S7（读档）、E5。
- **验收口径**（EPIC-4 原文 + ADR-3 + 探索 GDD §3.4）：存→读→存往返数据无损；写入中途强杀进程旧档可读出（任务管理器实测）；version 字段 + 迁移函数骨架就位。
- **测试要求**：GUT 12-15 用例（往返一致性、schema 字段对齐 SCHEMA 常量断言、损坏/缺失文件容错、原子写临时文件+rename 路径、version 迁移分支）。原子写"强杀"为人工实测项，GUT 覆盖到 rename 失败保留旧档分支。

### E4-S2 道路地图 · 2.5h（建议压缩 0.5h）
- **目标**：48×64 道路图：蜿蜒路线 + 断桥/石像地标；B1/B2 敌编组摆位。
- **依赖**：**S0**（克隆 gen_town → gen_road）。**被依赖**：S6（传送点位）。
- **验收口径**（探索 GDD §3.1 + §3.4）：实测走图 ~60s 主路径、8 个发现点间距达标（≈每 8s 一发现）；spawn 点周围 8 格无敌人初始位、无碰撞（制作校验项）。
- **测试要求**：GUT 4-6 用例（场景静态断言：宝箱 2/调查 3/敌人 3 对表、spawn 安全校验）；密度走图为人工实测留记录。

### E4-S3 遗迹三层地图 · 4.5h（建议压缩 0.5h）
- **目标**：f1 56×44 / f2 48×48 / f3 40×40，三层共用遗迹 tileset 与结构模板；开阔厅+窄走廊结构（服务"甩掉敌人"乐趣）；f3 为 Boss 前厅不放普通敌人。
- **依赖**：**S0**（gen_ruins 克隆）+ **遗迹 tileset 资产登记先行**（见风险 R1——开工前必须完成 OGA 选型登记，禁未登记先复制）。
- **验收口径**（探索 GDD §3.1/§3.2）：三层纵向推进"往深处去"暗示成立（结构自查）；各层宝箱/调查点对表（3+2+1 / 2 / 1；调查 4/3/2）；f2 精英定守位即交战位。
- **测试要求**：GUT 6-8 用例（三层点位数量对表自动化、f3 无普通敌人断言、f2 精英无巡逻 waypoints）；结构自查人工留记录。
- **⚠ 拍板挂钩**：遗迹入口是否预留回复点位置影响构图——建议回复点裁决在 S3 开工前完成（拍板项 ②）；未裁决则按冻结约束默认"不设"施工，预留入口 2×2 空地降低改图成本。

### E4-S4 敌人三态完整 AI · 1.5h
- **目标**：E2-S2 巡逻基础上补追击/放弃/回位与定守态。
- **依赖**：S2（道路敌人位可先测）；纯逻辑部分可用独立测试场景与 S3 并行。
- **验收口径**（探索 GDD §3.2 + 边缘 1）：追击 4 tile 半径 ±90° 伪视野、速 3 tile/s；卡墙 1.5s 或拉开 6 tile 放弃回位；敌人间互穿无碰撞。
- **测试要求**：GUT 10-12 用例（本 Sprint 最重逻辑 Story：追击触发/视野角边界、双放弃阈值、回位坐标、定守不动、互穿、战后 encounter_immunity 兜底配合）。

### E4-S5 宝箱/调查事件模板 · 2h（建议压缩 0.5h，文案移出）
- **目标**：宝箱/调查两个事件模板 + 27 个内容点位（9 宝箱 + 18 调查）全部可交互。
- **依赖**：S3（遗迹点位落位）+ S1（chests_opened 入档）；JSON 加载器（E5）**缺位时按 EPIC-4 授权走硬编码触发器先行，E5 完成后回迁**（拍板项 ④ 确认接受返工）。
- **验收口径**（探索 GDD §3.3 + 对话 GDD §3.2 动作白名单）：27 点位全部可交互，开启状态入存档（存→读→已开不重开）；~~调查文案至少 50% 为最终文案~~（**建议移出**：本 Sprint 全占位，最终文案归 E7-S2 弹性余量——需拍板）。
- **测试要求**：GUT 8-10 用例（27 点位参数化交互、not_flag 条件、give_item 落 GameData、set_flag + chests_opened 持久化往返）。

### E4-S6 传送网络 + 进图自动存档 · 2.5h
- **目标**：12 处传送全通 + "过传送点存，不进图即存"精确时序落地。
- **依赖**：S1 + S2 + S3（点位齐备）。**被依赖**：S7。
- **验收口径**（探索 GDD §3.4 + A5）：12 处全通、spawn 落位正确；自动存档时机实测 = 站在新图入口（teleport → 载入 → 落位 → `map_ready` → `save()`，非转场中间态）；存档图标右下角闪现 0.5s（§4）。
- **测试要求**：GUT 6-8 用例（12 处参数化传送、map_ready 时序信号、save 触发断言、胜利后立即存档时机）；图标闪现为人工验收。

### E4-S7 失败读档打通 · 1h
- **目标**：替换 E3-S3 占位失败流程——读 save.json → GameData 回灌 → Router 回图。
- **依赖**：S1 + S6（进图存档点必须先存在）+ E3 战败流程（已有）。**被依赖**：E6-S3（结算完善）。
- **验收口径**（战斗 GDD §3.5 + 对齐裁决 1 + 探索 GDD I3/边缘 3）：任意地图战败回该图入口存档点，状态=存档时状态；读档后 DialogueRunner 强制 IDLE（对话 GDD 边缘 5，系统未建则预留接口）。
- **测试要求**：GUT 4-6 用例（回灌后 map/position/party 一致、事件中断无残留 phase、DialogueRunner IDLE 预留位）；全流程人工实测留记录。

**GUT 新增合计：50-65 用例，收口预期 187 + ~57 ≈ 240（±10）。**

### ② EPIC-4 地图是否设免费回复点（两方案并列，不定案）
- **方案 A：不设（维持冻结约束 §6 I6「战斗间 HP/MP 不回满」现状）**

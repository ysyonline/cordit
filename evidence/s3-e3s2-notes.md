## 3. §3.1 队列规则的歧义与我的处理（主理人回传要求第 2 条）

### 歧义 1：击退目标恰好是「当前行动者」时怎么办？— 低风险
GDD §3.1 只写了「若已行动过，则下一轮起始位惩罚无效化」，没写正在行动的单位被击退会怎样。
**实际规则下不可能发生**（只有我方击退敌方，而我方行动时游标必然在我方身上）。
**我的处理**：把「正在行动」归入「已行动」，`idx <= cursor` 一律 no-op（原样返回）。
已写成单测 `test_击退只作用于尚未行动的当前轮` 的第二段，将来若规则变化会立刻红。

### 歧义 2：死者是「移除」还是「跳过」？— 中风险，措辞不一致
- §3.6 边缘 1：「跳过其行动，队列即刻重算预告条」
- §3.6 边缘 6：「从队列移除，其被跳过不产生任何结算」

两处措辞不同。**我的判断**：这是同一件事的两种描述——**机制上移除（边缘 6），效果上跳过（边缘 1）**。
边缘 1 的「预告条即刻重算」反过来支持移除（预告条里不该出现死者槽位）。
**我的处理**：统一实现为 `prune_dead()` 真移除，边缘 1 与 6 各写一条单测。

### 歧义 3（由歧义 2 派生，我认为是本 Story 第二重要的静默失败点）
移除死者后**必须修正游标**。若死者位于游标【之前】而不修正，游标会多走一格，
**静默吞掉一个活人的行动**——表现为「有人莫名其妙少打一回合」，不报错、不崩溃，
排查时极易被当成"队列偶发 bug"而不是游标算术。
**我的处理**：`prune_dead()` 返回 `{"queue", "cursor"}`，游标减去「游标之前被移除的个数」。
已写专门单测 `test_剔除死者时修正游标_不吞掉活人行动`（构造 cursor=2、下标 0 的 unit 死亡，断言游标从 2 修正到 1 而非跳到下一人）。

### 歧义 4：「后移 2 槽」的算术口径
我实现为「目标下标 +2」（remove 后 insert 到 `idx + 2`，等价于位置后移 2 格），
边界处由 `mini(idx + 2, size)` 钳到本轮末尾。
在 5 个以上单位时与「插到其后第 2 个后面」结果一致；边界处正是边缘 3 要覆盖的情形。

### 歧义 5：逃跑「平均 SPD」是否只算存活单位？
GDD §3.5 只说「我方平均 SPD − 敌方平均 SPD」。
**我的处理**：只统计存活单位（阵亡者不应影响「当前在场」的速度）。已写单测 `test_逃跑成功率只统计存活单位`。

### 歧义 6：伤害取整口径 — GDD 完全未提
**我的处理**：四舍五入（half away from zero），并写专门单测 `test_取整口径为四舍五入` 锁定。
这样将来换口径（比如改地板取整）会立刻红，而不是悄悄改变所有战斗数值。

### 歧义 7：中毒「可叠加时长」是累加还是刷新？— 中风险
GDD §3.6：「可叠加时长不可叠加伤害」。
**我的处理**：按字面实现为**累加**（3 + 3 = 6），**未设上限**。
理由：「叠加」不是「刷新」——若想表达刷新，通常写「重新计时」。
**风险**：B4 毒击权重 25%，若连续命中，中毒可能累积到 9~12 回合。若文策渊裁定为刷新或有上限，
改 `apply_poison()` 一行即可。已写单测 `test_中毒可叠加时长不可叠加伤害`。

### 歧义 8：中毒伤害的取整与下限
95 × 5% = 4.75 → 5（四舍五入）。下限 1——否则低血量时毒会变成空转（扣 0 但仍占状态）。

### 歧义 9：伤害结果的额外下限（我主动加的，偏离字面）
GDD 的 `max(1, ...)` 只写在 base 项上。我在**最终结果**也加了 `maxi(1, ...)`：
因为抗性 ×0.5 或防御 ×0.5 后可能算出 0，而本系统无 MISS（§4.6），
「造成 0 伤害」只会被当成 bug。已写单测 `test_伤害下限为1_不出现0伤害`。

## 5. 本轮发现的项目级风险：GUT 会静默跳过坏掉的测试脚本（已加防护）

**现象**：测试脚本若存在**解析错误**或**未继承 GutTest**，GUT 只打一条 WARNING 就跳过整个文件，
`Run Summary` 依然报 `All tests passed`、退出码 0。

**我真实踩到**：`test_e3s2.gd` 因函数名含非法字符 `%`（`test_中毒每回合扣最大HP的5%`）
导致解析失败，**整份 56 条用例被静默跳过**，而当时跑测全绿、退出码 0。
第一次跑完后 `Scripts 7 / Tests 95 / All tests passed`——如果没去核对脚本数，这就漏过去了。

**已加防护**：在 `tests/gut/test_sanity.gd` 新增哨兵用例
`test_sanity_所有测试脚本都能被GUT收集`——扫描 `res://tests/gut/*.gd`，逐个 `load()` 并实例化，
断言非 null 且 `is GutTest`。解析失败在此处会变成**显式 FAIL**，而不是一条没人看的 WARNING。

**已做负向验证**（证明哨兵真的会红，不是装饰）：
临时放入一个坏脚本 → `151 passing / 1 failing`、退出码 **1**；移除后 → `152/152`、退出码 **0**。

**建议**（供你决定是否采纳）：把「跑完必须核对 Scripts 数」写进 tests/README 的留档纪律，
否则将来有人在别的目录加测试脚本时仍可能踩到。哨兵只覆盖 `tests/gut/`。

## 7. 给下游的提示（E3-S3 四指令 + 三结局结算）

1. **查表入口**：`BattleUnits.build_party(level)` 与 `BattleUnits.build_encounter(encounter_id)`
   直接得到单位字典数组；`BattleUnits.is_escape_forbidden(id)` 查 Boss 禁逃（读编组表的 `is_boss`）。
2. **推荐推进循环**：`build_queue` → 逐单位结算 → `advance(queue, cursor, party, enemies)`
   → `round_over` 为真时重建下一轮。`advance()` 内含剔除与游标修正，**不要自己写 cursor+1**。
3. **轮末必须调** `reset_round_flags()` 清 `defending/covering`——泄漏会导致永久减伤 50%。
4. **随机由调用方注入**：伤害传 `BattleLogic.variance_from_roll(rng.randf())`，
   逃跑传 `BattleLogic.escape_success(party, enemies, rng.randf())`。core 层一个随机 API 都没有。
5. **`is_boss` 在编组表不在敌人表**——置灰逃跑菜单查编组。
6. 边缘 2/4/5/7（掩护致死、MP 不足置灰、道具耗尽、我方全灭中断敌方结算）属 E3-S3，
   本 Story 已备好地基：`incoming_damage_multiplier()`、`is_wiped()`、`reset_round_flags()`。
   `is_wiped([])` 返回 true（空数组视为全灭，防御式）。
7. 敌方行为倍率（群击 0.7 / 重击 1.8 / 蓄力 0.0）在 `EnemyData.ACTION_CATALOG`，
   仍是 E3-S1 遗留的**待裁定工程初值**。
